# WeekFit Assistant — спецификация диалогов v2

**Дата:** 6 октября 2026  
**Статус:** дизайн для реализации (не код)  
**Язык UI:** русский  
**Исходник:** `WeekFit_Assistant_Dialogue_Tree.md` v1 — критически переработан

---

## 0. Что изменено относительно v1

| Проблема v1 | Решение v2 |
| --- | --- |
| 90+ узлов, много одношаговых «Продолжить» | ~45 узлов; автопереход там, где нет выбора |
| Отдельные листья `R_LATE` / `R_EARLY` / `R_BROKEN` с почти одинаковым итогом | Один узел `R_SLEEP_FACTOR` с вариантами текста |
| Цепочки `A_AFTER` → `A_CROSS`, `A_BOTH` → `A_CROSS` | Один узел `A_LOAD_RECOVERY` |
| Частые «Понял» без новой информации | Наблюдение из данных + смысл ответа |
| Меню и чипы смешаны | Глобальное меню отдельно; в реплике 2–4 основные кнопки |
| Weekly focus / лишние обещания | Убраны; завершение без обязательного действия |
| Опрос каждый день одинаковый | Политика повторного входа: данные → короткое обновление → углубление по запросу |

Критерий успеха для каждой завершённой ветки:

> «Вот что видно по данным. Вот как это соотносится с целью / обычным уровнем. Вот что это значит с учётом моего ответа.»

## 1. Карта сценариев

| Потребность человека | Данные | Полезный итог |
| --- | --- | --- |
| Понять нагрузку сегодня / за период | Тренировки, план, шаги (если есть) | Объём vs план/обычное + как ощущалась нагрузка |
| Понять, почему тяжело при «обычном» объёме | Тренировки + сон/восстановление | Сопоставление без ложной причинности |
| Хочет больше нагрузки | Объём, интервалы, восстановление | Текущая точка отсчёта; без автоизменения плана |
| Понять питание к цели | Калории/белок, полнота лога, цели | Промежуточный или дневной статус относительно цели |
| День записан не полностью | Флаг полноты | Ясное ограничение: цифры только по записанному |
| Понять сонливость / усталость | Сон, (опц.) recovery, нагрузка | Совпадение или расхождение ощущений и показателей |
| Показатели «плохие», самочувствие хорошее | Recovery/сон + feeling | Не спорить с ощущением; назвать расхождение |
| Нет данных | Missing / stale | Что известно, чего нельзя заключить; опционально открыть экран |
| Ничего не изменилось с прошлого раза | Diff signals | Короткое обновление без повторного опроса |

## 2. Состояние разговора (контекст)

```
conversation_id
day_key
feeling: good | okay | tired | low | null
fatigue_type: sleepy | body | focus | mixed | mood | null
fatigue_duration: today | few_days | often | null
area: activity | nutrition | recovery | null
previous_area
period: { kind, start, end, completeness }
answers: { question_id → value, answered_at, ttl }
observations_shown: [observation_id]
data_fingerprint: hash(vitals + plan + meals + activities)
return_node_id
last_conclusion
```

**TTL ответов (по умолчанию):**
- feeling — до конца календарного дня  
- food_log_complete_until_now — до следующего приёма пищи / 4 ч / смены дня  
- day_eating_finished — до конца дня  
- fatigue_type / duration — 24 ч или до смены feeling  
- workout_effort — привязан к конкретной сессии / дню  

**Правило пропуска:** если `answers[question_id]` валиден по TTL — не задавать вопрос снова.

## 3. Placeholders

| Placeholder | Источник | Период | Ед. | Полнота / свежесть | Если нет значения |
| --- | --- | --- | --- | --- | --- |
| `{name}` | Profile | — | — | непустое имя | не вставлять обращение |
| `{greeting}` | локальное время | сейчас | — | 05–11 утро / 12–16 день / иначе вечер | «Привет» |
| `{feeling_label}` | ответ HELLO | сегодня | — | — | — |
| `{steps_today}` | HealthKit / устройство | календарный день | шаги | день неполный → помечать | «данных о шагах нет» |
| `{steps_average_7d}` | то же | 7 **завершённых** дней | шаги | ≥4 дня с данными | не сравнивать «с обычным» |
| `{steps_personal_baseline}` | история приложения | согласованная аналитика | шаги | **[нужен порог из app analytics]** | только абсолютные факты |
| `{workouts_completed}` | план + HK, дедуп | выбранный period | шт. / мин | completed ≠ planned | «записанных тренировок нет» |
| `{workouts_planned}` | план | period | шт. | план ≠ факт | «в плане на период ничего нет» |
| `{workout_label}` | title/type + duration | сессия | — | значимая сессия | «активность» |
| `{workout_minutes}` | effectiveDuration | сессия | мин | — | не упоминать длительность |
| `{protein_logged_today}` | Meals / HK nutrition | сегодня | г | только записанное | «белок пока не записан» |
| `{protein_target}` | цели профиля | день | г | цель > 0 | не сравнивать с целью |
| `{calories_logged_today}` | то же | сегодня | ккал | — | «калории пока не записаны» |
| `{calories_target}` | цели | день | ккал | цель > 0 | без оценки «достаточно» |
| `{meals_logged_count}` | записи | день | шт. | — | 0 |
| `{sleep_duration_last_night}` | HK sleep | прошлая ночь | ч:мин | fresh ≤36 ч **[согласовать с CoachFeelingEvidenceRules]** | «сна за прошлую ночь нет» |
| `{sleep_personal_baseline}` | история | согласованная аналитика | ч:мин | min samples **[из app]** | без «короче/длиннее обычного» |
| `{recovery_percent}` | HealthManager / observation | сегодня | % | не считать missing = 0 | «показателя восстановления нет» |
| `{recovery_baseline}` | история | — | % | то же | без сравнения с обычным |
| `{period_label}` | выбранный period | — | текст дат | — | «сегодня» |
| `{data_limit_note}` | флаги полноты | — | текст | один раз за ветку | пусто |

**Запрещено:** подставлять 0 вместо missing; сравнивать неполный день с завершённым; сравнивать текущую неполную неделю с полной.

## 4. Глобальное меню (не чипы реплики)

| Действие | Эффект |
| --- | --- |
| Другая тема | → `TOPIC`; сохранить feeling и answers; сменить `area` |
| Назад | предыдущий user-answered узел; пересчитать реплику |
| Изменить ответ | выбрать question_id → инвалидировать зависимые answers/выводы |
| Начать заново | новый `conversation_id` → `HELLO` |
| Завершить | → `END` |

## 5. Дерево узлов

Условные обозначения кнопок:  
`[ответ]` · `[навигация]` · `[действие]`

### 5.1 Вход и оболочка

#### `START` (router)
**Вход:** открытие Assistant  
1. Есть незавершённый разговор сегодня → `RESUME`  
2. Иначе → `HELLO`

#### `RESUME`
**Реплика:** «Мы остановились на {area_label}. Продолжим?»  
**Кнопки:**  
- Продолжить `[навигация]` → `RESTORE`  
- Начать заново `[навигация]` → `HELLO` (новый контекст)

#### `RESTORE` (action)
Восстановить `return_node_id`.  
- fingerprint данных тот же → `RESTORED_NODE`  
- изменился → `REFRESH`

#### `REFRESH`
**Реплика:** «С прошлого раза обновились данные. Обновим разбор?»  
**Кнопки:**  
- Да `[ответ]` → `AREA_ENTRY` (текущая area)  
- Оставить прежний `[ответ]` → `RESTORED_NODE`

#### `HELLO`
**Реплика:** «{greeting}, {name}. Как ты сегодня?»  
(без имени: «{greeting}. Как ты сегодня?»)  
**Кнопки:**  
- Хорошо → сохранить `feeling=good` → `TOPIC`  
- Нормально → `feeling=okay` → `TOPIC`  
- Устал → `feeling=tired` → `TOPIC`  
- Не очень → `feeling=low` → `TOPIC`  

**Fallback:** меню «Завершить» → `END`

#### `TOPIC`
**Реплика:** «С чего начнём?»  
**Кнопки:**  
- Активность → `area=activity` → `A_ENTRY`  
- Питание → `area=nutrition` → `N_ENTRY`  
- Восстановление → `area=recovery` → `R_ENTRY`

#### `AREA_ENTRY` (router)
По `area` → `A_ENTRY` / `N_ENTRY` / `R_ENTRY`

#### `END`
**Реплика:**  
- если есть `last_conclusion` — повторить его одной фразой без нового совета;  
- иначе: «Хорошо, на этом остановимся.»  
**Кнопки:** нет (или только «Новый разговор» → `HELLO`)

### 5.2 Activity

#### `A_ENTRY` (router)
1. Нет свежих тренировок/шагов/плана → `A_MISSING`  
2. Иначе → `A_BRIEF`

#### `A_MISSING`
**Реплика:** «Свежих записей об активности пока нет.» + опц. «Последние — за {date}.»  
**Кнопки:**  
- Прошлые дни `[навигация]` → `A_BRIEF` (period=history) *если есть история*  
- Проверить данные `[навигация]` → `CONNECTION`  
- Другая тема → `TOPIC`  
- На этом всё → `END`

#### `A_BRIEF`
**Реплика (шаблон, 1–2 предложения):**  
1 факт (тренировки / план / движение) + при feeling=tired/low мягкая связка без диагноза.  
Пример каркаса: «Сегодня записано: {workout_label}, {workout_minutes} мин. В плане на сегодня: {workouts_planned}.»  
**Кнопки:**  
- Тренировки `[навигация]` → `A_WORKOUT` *если есть completed или planned*  
- Движение `[навигация]` → `A_STEPS` *если есть шаги или можно сказать об отсутствии*  
- Неделя `[навигация]` → `A_WEEK` *если period допускает*  
- Подвести итог → `A_RESULT`

#### `A_WORKOUT`
**Вход:** есть completed **или** planned.  
**Если completed=0 и planned≥0:** → `A_NO_WORKOUT`  

**Реплика:** «{workouts_completed} · {суммарные минуты}. {сравнение с планом или baseline, если допустимо}. Как ощущалась нагрузка?»  
**Кнопки:**  
- Комфортно `[ответ]` → `effort=comfortable` → `A_RESULT` (или `A_SPACING` если просят детали — см. ниже)  
- Тяжеловато `[ответ]` → `A_HARD`  
- Хочется больше `[ответ]` → `A_MORE`  
- Не уверен `[ответ]` → `A_RESULT` с ограничением  

Упрощение v2: после «Комфортно» сразу итог; деталь «Как распределены?» — кнопка на `A_RESULT`: «Посмотреть распределение» → `A_SPACING`.

#### `A_NO_WORKOUT`
**Реплика:** «За {period_label} записанных тренировок нет. Ты занимался без записи?»  
**Кнопки:**  
- Да → `A_UNRECORDED`  
- Нет → `A_NONE`  
- Не помню → `A_RESULT` (ограничение)

#### `A_UNRECORDED`
**Реплика:** «Тогда записи не показывают всю нагрузку. По ним нельзя оценить все тренировки.»  
**Кнопки:** Подвести итог → `A_RESULT` · Другая тема · На этом всё

#### `A_NONE`
**Реплика:** «Тренировок за период не было.» + если план: «В плане было {workouts_planned}.»  
**Кнопки:** Движение → `A_STEPS` *если доступно* · На этом всё

#### `A_HARD`
**Реплика:** «Когда больше чувствовалась усталость?»  
**Кнопки:**  
- Во время → `A_LOAD_RECOVERY` (`hard_when=during`)  
- После → `A_LOAD_RECOVERY` (`hard_when=after`)  
- И во время, и после → `A_LOAD_RECOVERY` (`hard_when=both`)  
- Трудно сказать → `A_RESULT`

#### `A_LOAD_RECOVERY` *(объединяет A_DURING/NEW/SAME/AFTER/BOTH/CROSS)*
**Реплика:** факты объёма/интервалов + сон за те же даты **или** честный gap.  
Если `hard_when=during`: «Было что-то новое в самой тренировке?»  
- Новое / Как обычно / Не уверен → сохранить `novelty` → итог-фраза в том же узле или сразу `A_RESULT`  

**Кнопки после факта:**  
- Разобрать восстановление → `R_ENTRY` (передать fatigue hints)  
- Подвести итог → `A_RESULT`

#### `A_MORE`
**Реплика:** «Что хочется изменить?»  
**Кнопки:** Чаще / Дольше / Сложнее / Пока не знаю → `A_MORE_CONTEXT`

#### `A_MORE_CONTEXT`
**Реплика:** текущий показатель выбранного изменения + план/история если есть. Явно: это точка отсчёта, не согласие менять план.  
**Кнопки:** Посмотреть план `[действие]` → `OPEN_PLAN` · Восстановление → `R_ENTRY` · На этом всё

#### `A_STEPS`
**Реплика:** «{steps…}. Это похоже на то, как прошли дни?»  
**Кнопки:**  
- Много сидел → `A_RESULT` (согласовать с данными)  
- Больше ходил → `A_RESULT`  
- Двигался без устройства → `A_RESULT` + limit_note  
- Как обычно → `A_RESULT`  
- Не помню → `A_RESULT`

Нет шагов → `A_STEPS_MISSING` (тренировки / подключение / конец).

#### `A_WEEK`
**Реплика:** один абзац: тренировки + движение + одно ограничение полноты.  
**Кнопки:** Тренировки · Движение · Подвести итог

#### `A_SPACING`
**Реплика:** дни и интервалы.  
**Кнопки:** Подвести итог · Восстановление

#### `A_RESULT`
**Реплика:** факт → ориентир → ответ человека → ограничение (если влияет).  
Сохранить `last_conclusion`.  
**Кнопки:** Другая тема · Открыть план *если уместно* · На этом всё

### 5.3 Nutrition

#### `N_ENTRY` (router)
1. Сегодня 0 записей → `N_EMPTY`  
2. Иначе → `N_COMPLETE`

#### `N_EMPTY`
**Реплика:** «Сегодня еда пока не записана.»  
**Кнопки:** Прошлые дни → `N_WEEK` *если есть* · Добавить еду `[действие]` → `OPEN_MEALS` · На этом всё

#### `N_COMPLETE`
**Реплика:** «Сегодня записано приёмов: {meals_logged_count}. Всё, что ты ел до этого момента, уже в дневнике?»  
**Кнопки:**  
- Да → `food_complete_until_now=true` → `N_SCOPE`  
- Нет → `N_PARTIAL`  
- Не уверен → `N_PARTIAL`

#### `N_PARTIAL`
**Реплика:** «Тогда цифры описывают только записанное.»  
**Кнопки:** Добавить еду → `OPEN_MEALS` · Смотреть записанное → `N_RECORDED` · Прошлые дни → `N_WEEK`

#### `N_RECORDED`
**Реплика:** «В записях: {calories_logged_today} ккал, белка {protein_logged_today} г. Это не весь рацион.»  
**Кнопки:** Добавить еду · На этом всё · Другая тема

#### `N_SCOPE`
**Реплика:** «Посмотрим сегодня или последние дни?»  
**Кнопки:** Сегодня → `N_DAY` · 7 дней → `N_WEEK`

#### `N_DAY`
**Реплика:** «Ты ещё планируешь есть сегодня?»  
**Кнопки:**  
- Да / Пока не знаю → `N_PROGRESS` (день открыт)  
- Нет, на сегодня всё → `day_finished=true` → `N_PROGRESS`

#### `N_PROGRESS` *(объединяет N_ONGOING / N_FINISHED + выбор метрики)*
**Реплика:**  
- открытый день: «К этому моменту: {cal}, белка {pro}. День ещё открыт — это промежуточные цифры.»  
- закрытый: «За день: {cal} / {pro}. {ориентиры целей, если есть}.»  
**Кнопки:** Калории → `N_CAL` · Белок → `N_PROTEIN` · Блюда → `N_MEALS` · Итог → `N_RESULT`

#### `N_CAL` / `N_PROTEIN` / `N_MEALS`
Короткий разбор по правилам выше/около/ниже **только** при допустимой полноте; иначе — абсолют + ограничение.  
**Кнопки:** другие метрики · Итог → `N_RESULT`

#### `N_WEEK`
Если записей нет → `N_NO_HISTORY`.  
**Реплика:** «Записи есть за {n} из 7 дней. Насколько они полные?»  
**Кнопки:** Всё записано → `N_WEEK_VIEW` · Только некоторые → `N_PICK_DAYS` · Не уверен → `N_WEEK_PARTIAL`

#### `N_PICK_DAYS`
Мультивыбор дат (+ «Ни одного»). → `N_WEEK_VIEW` или `N_WEEK_PARTIAL`

#### `N_WEEK_PARTIAL` / `N_WEEK_VIEW`
Факты только по допустимому набору.  
**Реплика (full):** «… Эта неделя похожа на твоё обычное питание?»  
**Кнопки:** Да / Нет, необычная / Не уверен → варианты результата · Итог

#### `N_RESULT`
Шаблон итога питания.  
**Кнопки:** Открыть записи `[действие]` · Другая тема · На этом всё

### 5.4 Recovery

#### `R_ENTRY` (router)
1. Нет свежих sleep/recovery → `R_MISSING`  
2. feeling ∈ {tired, low} и fatigue_type ещё нет → `R_TIRED`  
3. feeling ∈ {tired, low} и fatigue_type есть → `R_KNOWN`  
4. Иначе → `R_BRIEF`

#### `R_MISSING`
Аналогично activity missing (история / подключение / другая тема / конец).

#### `R_BRIEF`
**Реплика:** 1–2 факта (сон / recovery) + сравнение с baseline **если допустимо**.  
Если feeling=good/okay и recovery ниже обычного: назвать расхождение, не спорить.  
**Кнопки:** Сон · Показатель *если есть* · 7 дней · Чувствую усталость → `R_TIRED` · Итог

#### `R_TIRED`
**Реплика:** краткий факт + «Что больше ощущается?»  
**Кнопки:**  
- Хочется спать → `fatigue_type=sleepy` → `R_DURATION`  
- Устало тело → `body` → `R_DURATION`  
- Трудно сосредоточиться → `focus` → `R_DURATION`  
- Всего понемногу → `mixed` → `R_MIX`  
- (если feeling=low) Скорее настроение → `R_MOOD`  
- Сложно сказать → `R_MIX`

#### `R_DURATION`
Пропуск, если уже есть.  
**Реплика:** «Это только сегодня или уже несколько дней?»  
**Кнопки:** Только сегодня / Несколько дней / Часто так бывает → дальше по типу

#### `R_SLEEP_PATH` *(sleepy)*
Показать сон за период.  
Router:  
- сон короче baseline (если baseline есть) → `R_SLEEP_FACTOR`  
- иначе → `R_NO_SLEEP_EXPLAIN`

#### `R_SLEEP_FACTOR` *(объединяет LATE/EARLY/BROKEN/UNKNOWN)*
**Реплика:** «Сон был короче обычного. Что изменилось?»  
**Кнопки:** Позже ложился / Раньше вставал / Просыпался / Не знаю  
→ одна итоговая реплика-вариант → `R_RESULT`

#### `R_NO_SLEEP_EXPLAIN`
Сон обычный или нет базы — усталость этими данными не объясняется.  
**Кнопки:** Посмотреть нагрузку → `R_LOAD` · Итог

#### `R_BODY` / `R_LOAD`
Связь с тренировками (пропуск вопроса, если уже из Activity). Сопоставление нагрузки и сна без причинности → `R_RESULT`

#### `R_FOCUS` / `R_MIX` / `R_MOOD` / `R_SLEEP` / `R_SCORE` / `R_WEEK`
Как в v1 по смыслу, но короче; `R_WEEK` спрашивает субъективную разницу → better/worse/stable/unsure → `R_RESULT` (без повторного `R_TIRED`, если тип уже известен).

#### `R_RESULT`
Итог восстановления.  
**Кнопки:** Активность · Другая тема · На этом всё

---

### 5.5 Система

#### `CONNECTION` → `OPEN_SETTINGS` / `REFETCH` / назад в area  
#### `REFETCH` → данные есть? `AREA_ENTRY` : `FETCH_EMPTY`  
#### `OPEN_PLAN` / `OPEN_MEALS` — только существующие экраны; не менять план/еду автоматически  
#### `RETURN` / `ACTION_FAILED` — как в v1

**Требует проверки в коде:** экран «подключение Health»; отметка полноты еды по дням; точные пороги baseline; доступность intensity. Пока функции нет — скрыть кнопку.

## 6. Полные примеры разговоров

Числа вымышленные и согласованные.

### 6.1 Activity — обычный успешный путь

1. **А:** Добрый вечер, Макс. Как ты сегодня?  
   **К:** Хорошо / Нормально / Устал / Не очень  
2. **П:** Нормально  
3. **А:** С чего начнём?  
4. **П:** Активность  
5. **А:** Сегодня записана тренировка «Силовая», 48 мин. В плане на сегодня она одна.  
   **К:** Тренировки / Движение / Неделя / Подвести итог  
6. **П:** Тренировки  
7. **А:** 1 тренировка, 48 мин — по плану. Как ощущалась нагрузка?  
   **К:** Комфортно / Тяжеловато / Хочется больше / Не уверен  
8. **П:** Комфортно  
9. **А:** Нагрузка совпала с планом, и тебе было комфортно. На сегодня этого достаточно.  
   **К:** Другая тема / Открыть план / На этом всё  
10. **П:** На этом всё  

### 6.2 Activity — неполные данные

1. … → Активность  
2. **А:** Свежих записей об активности пока нет. Последние — за 4 октября.  
3. **П:** Прошлые дни  
4. **А:** За 4 октября: прогулка 84 мин. Записанных силовых не было. Как ощущалась нагрузка?  
5. **П:** Не уверен  
6. **А:** По записям видна прогулка 84 мин. Как она далась — пока нельзя уточнить по твоим ответам.  
7. **П:** На этом всё  

### 6.3 Activity — ощущения ≠ объём + смена темы

1. Feeling: Устал → Активность  
2. **А:** Сегодня 2 тренировки, суммарно 70 мин — больше, чем вчера (40 мин).  
3. **П:** Тренировки → Тяжеловато → После  
4. **А:** Между тренировками был короткий промежуток. Сон прошлой ночи: 5 ч 40 мин — меньше твоего обычного ~7 ч. Это может сочетаться с усталостью, но само по себе не доказывает причину.  
5. **П:** Другая тема → Восстановление  
6. *(Recovery использует уже известную усталость «после тренировок», не спрашивает заново тип)*  

### 6.4 Nutrition — успешный путь (день ещё идёт)

1. Feeling: Хорошо → Питание  
2. **А:** Сегодня записано приёмов: 2. Всё, что ты ел до этого момента, уже в дневнике?  
3. **П:** Да  
4. **А:** Посмотрим сегодня или последние дни?  
5. **П:** Сегодня  
6. **А:** Ты ещё планируешь есть сегодня?  
7. **П:** Да  
8. **А:** К этому моменту: 820 ккал, белка 38 г при цели 120 г. День ещё открыт — это промежуточные цифры.  
9. **П:** Белок  
10. **А:** До цели белка остаётся заметный запас. Чаще всего белок у тебя ближе к обеду и ужину — сейчас рано судить о дне.  
11. **П:** Подвести итог  
12. **А:** На сейчас белок 38 из 120 г, дневник до текущего момента полный. День не закончен — итог рациона ещё впереди.  

### 6.5 Nutrition — неполный лог

1. … → Питание → «Не всё»  
2. **А:** Тогда цифры описывают только записанное.  
3. **П:** Смотреть записанное  
4. **А:** В записях: 450 ккал, белка 18 г. Это не весь рацион.  
5. **П:** На этом всё  

### 6.6 Nutrition — цели достигнуты, ничего менять не нужно

1. День закрыт, калории 2050/2000, белок 125/120, лог полный  
2. **А:** За день: 2050 ккал и 125 г белка — около твоих ориентиров.  
3. **П:** Подвести итог  
4. **А:** По записям день закрыт близко к целям. Менять рацион по этим цифрам не требуется.  

### 6.7 Recovery — обычный путь (сонливость + короткий сон)

1. Feeling: Устал → Восстановление  
2. **А:** Прошлой ночью сон 5 ч 50 мин; обычно у тебя около 7 ч. Что больше ощущается?  
3. **П:** Хочется спать → Только сегодня  
4. **А:** Сон короче обычного. Что изменилось?  
5. **П:** Позже ложился  
6. **А:** Ты позже ложился, а подъём почти не сдвинулся — на сон осталось меньше времени. Это согласуется с сегодняшней сонливостью, но не закрывает все возможные причины.  
7. **П:** На этом всё  

### 6.8 Recovery — показатели ниже, самочувствие хорошее

1. Feeling: Хорошо → Восстановление  
2. **А:** Показатель восстановления 58% — ниже твоего обычного ~70%. Ты чувствуешь себя хорошо, хотя ориентир ниже. Что посмотрим?  
3. **П:** Подвести итог  
4. **А:** Ориентир восстановления ниже обычного, но самочувствие хорошее. Будем опираться на то, как ты себя чувствуешь, и просто заметим расхождение в данных.  

### 6.9 Recovery — только сон; усталость не объясняется

1. Нет recovery %, есть сон ~ обычный; Feeling: Устал → тело  
2. **А:** Сон близок к обычному. По этим данным физическую усталость объяснить не получается.  
3. **П:** Посмотреть нагрузку  
4. **А:** Вчера силовая 55 мин. Связь возможна, но не доказана.  
5. **П:** Подвести итог  

### 6.10 Исправление ответа

1. На `N_COMPLETE` ответил «Да» → позже меню «Изменить ответ» → снова `N_COMPLETE`  
2. Ответ «Нет» инвалидирует `food_complete_until_now` и выводы `N_PROGRESS`  
3. Внешние действия (добавленная еда) не откатываются  

### 6.11 Повторный вход без изменений

1. `RESUME` → Продолжить → fingerprint тот же → тот же узел  
2. Если разговор уже имел итог и данные не изменились: допускается короткий `REFRESH`-skip: «С прошлого раза существенных изменений в данных нет.» → TOPIC или END

## 8. Проверка качества

| Критерий | Статус дизайна |
| --- | --- |
| У каждой кнопки есть целевой узел | Да (в дереве v2) |
| Нет автоциклов без действия человека | Router только с fallback; REFETCH ограничен FETCH_EMPTY |
| Каждый ответ меняет продолжение или итог | Убраны пустые «Продолжить» |
| Нет повторных вопросов при валидном TTL | RULE §2 + R_KNOWN / skip duration |
| Итог соответствует данным и ответам | Шаблон §итог |
| Можно закончить без действия | END на всех ветках missing/result |
| Человек понимает положение | Критерий успеха §0 |
| Feeling не форсит изменение плана | A_MORE_CONTEXT явно |
| Missing ≠ 0 | Placeholders §3 |
| Корреляция ≠ причина | Copy constraints в A_LOAD_RECOVERY / R_LOAD |

## 9. Политика ежедневного использования

1. Не начинать каждый день с полного опроса областей.  
2. `HELLO` — коротко; если fingerprint дня ≈ вчерашнему итогу и feeling тот же — после TOPIC можно предложить «Короткое обновление» (1 факт) вместо углубления.  
3. Не поднимать старую проблему без нового сигнала или явного выбора темы.  
4. Разнообразие = выбор сценария (workout vs steps vs sleep mismatch), не синонимы одной фразы.  
5. Не обещать «проверим завтра» без реального механизма напоминаний.

## 10. Порядок реализации (для программирования)

1. Каркас: `START…TOPIC…END`, меню, context TTL.  
2. `A_ENTRY → A_BRIEF → A_WORKOUT/STEPS → A_RESULT` (минимальный happy path).  
3. `N_ENTRY → N_COMPLETE → N_DAY → N_PROGRESS → N_RESULT`.  
4. `R_ENTRY → R_BRIEF / R_TIRED → R_RESULT`.  
5. Missing/partial/stale + OPEN_* + RESUME/REFRESH.  
6. Cross-area handoff Activity→Recovery без повторных вопросов.  
7. Подключить реальные baseline/пороги из аналитики приложения; до этого — только абсолютные факты.

## 11. Открытые вопросы к продукту/коду

1. Минимальные правила personal baseline (сколько дней, какие метрики) — **взять из существующей аналитики**, не задавать в диалоге.  
2. Есть ли отдельный экран разрешения Health / «подключение»?  
3. Как пользователь отмечает «день еды закончен» вне ассистента?  
4. Мультивыбор дней полноты еды — новый UI или упростить до «некоторые/не уверен» без пикера?  
5. Глобальное меню (Назад / Изменить ответ) — нужен UI-паттерн в чате.
